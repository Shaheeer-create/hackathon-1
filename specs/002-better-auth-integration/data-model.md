# Data Model: Better Auth Integration

## Entities

### User
Represents a registered user in the system.

**Attributes:**
- `id`: string (primary key, auto-generated by Better Auth)
- `name`: string (user's display name)
- `email`: string (unique, validated email address)
- `emailVerified`: boolean | null (whether email has been verified)
- `image`: string | null (profile image URL)
- `createdAt`: Date (account creation timestamp)
- `updatedAt`: Date (last update timestamp)

### Technical Background
Represents the user's technical profile for personalization.

**Attributes:**
- `userId`: string (foreign key referencing User.id)
- `softwareSkills`: string[] (array of software skills)
- `hardwareExperience`: string[] (array of hardware experiences)
- `createdAt`: Date (record creation timestamp)
- `updatedAt`: Date (last update timestamp)

### Session
Represents an authenticated user session.

**Attributes:**
- `id`: string (primary key, auto-generated by Better Auth)
- `userId`: string (foreign key referencing User.id)
- `expiresAt`: Date (session expiration timestamp)
- `ipAddress`: string | null (IP address of the session)
- `userAgent`: string | null (user agent string of the session)
- `createdAt`: Date (session creation timestamp)

## Relationships

### User → Technical Background
- One-to-One relationship
- A User has one Technical Background
- Foreign key: TechnicalBackground.userId → User.id

### User → Session
- One-to-Many relationship
- A User can have multiple Sessions
- Foreign key: Session.userId → User.id

## Validation Rules

### User Validation
- `name`: Required, minimum 2 characters, maximum 50 characters
- `email`: Required, must be a valid email format, unique
- `emailVerified`: Default to null, updated when user verifies email

### Technical Background Validation
- `softwareSkills`: Required, array of strings, minimum 1 skill
- `hardwareExperience`: Required, array of strings, minimum 1 experience
- `userId`: Required, must reference an existing User

### Session Validation
- `userId`: Required, must reference an existing User
- `expiresAt`: Required, must be a future date

## State Transitions

### User States
- `Unverified`: User has signed up but not verified email
- `Active`: User has verified email and can access all features
- `Suspended`: User account has been suspended (not implemented in this feature)

### Session States
- `Active`: Session is valid and user is authenticated
- `Expired`: Session has passed its expiration time
- `Terminated`: Session was explicitly ended by user or system

## Indexes

### User
- Email: Unique index on `email` field for fast lookups and uniqueness enforcement

### Session
- User ID: Index on `userId` for fast session retrieval by user
- Expiration: Index on `expiresAt` for efficient cleanup of expired sessions
