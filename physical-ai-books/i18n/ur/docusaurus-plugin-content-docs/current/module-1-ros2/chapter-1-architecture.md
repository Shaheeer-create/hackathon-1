# باب 1: ROS 2 آرکیٹیکچر تصورات

## جائزہ

یہ باب ROS 2 (روبوٹ آپریٹنگ سسٹم 2) کے بنیادی تصورات کو متعارف کراتا ہے، جو ہمارے ہیومنوائڈ روبوٹکس سسٹم کے لیے مڈل ویئر کے طور پر کام کرتا ہے۔ ROS 2 وہ مواصلاتی بنیاد فراہم کرتا ہے جو ہمارے روبوٹ کے مختلف اجزاء کو بے رکاوٹ کام کرنے کی اجازت دیتا ہے۔

## ROS 2 کیا ہے؟

ROS 2 روبوٹ آپریٹنگ سسٹم کی اگلی نسل ہے، جسے ROS 1 کی حدود کو حل کرنے اور روبوٹکس کی ترقی کے لیے زیادہ مضبوط، قابل توسیع اور پیداوار کے لیے تیار فریم ورک فراہم کرنے کے لیے ڈیزائن کیا گیا ہے۔ ROS 1 کے برعکس، جسے بنیادی طور پر تحقیقی ماحول کے لیے ڈیزائن کیا گیا تھا، ROS 2 کو صنعتی ایپلی کیشنز کو ذہن میں رکھ کر تیار کیا گیا ہے۔

## کلیدی تصورات

### نوڈس
نوڈس ROS 2 سسٹم کے بنیادی عمارتی بلاک ہیں۔ ہر نوڈ عام طور پر ایک مخصوص فنکشن انجام دیتا ہے، جیسے سینسر ڈیٹا کی پروسیسنگ، موشن منصوبہ بندی، یا کنٹرول۔ نوڈس مختلف پروگرامنگ زبانوں (C++، پائی تھون، وغیرہ) میں لکھے جا سکتے ہیں اور ٹاپکس، سروسز، اور ایکشنز کے ذریعے ایک دوسرے سے رابطہ کر سکتے ہیں۔

### ٹاپکس
ٹاپکس نوڈس کے درمیان ایک بے ترتیب، بہت سے سے بہت سوں کی مواصلات کو ایک شائع کنندہ-سبسکرائیب کے پیٹرن کا استعمال کرتے ہوئے فعال کرتے ہیں۔ شائع کنندہ ایک ٹاپک پر پیغامات بھیجتے ہیں، اور سبسکرائیبرز ان ٹاپک سے پیغامات وصول کرتے ہیں۔ یہ نوڈس کو ایک دوسرے سے الگ کر دیتا ہے، لچکدار سسٹم آرکیٹیکچر کی اجازت دیتا ہے۔

### سروسز
خدمات نوڈس کے درمیان ہم وقت، درخواست-جواب کی مواصلات فراہم کرتی ہیں۔ ایک کلائنٹ ایک سروس پر ایک درخواست بھیجتا ہے، اور سروس درخواست کو پروسیس کرتی ہے اور ایک جواب لوٹاتی ہے۔ یہ فوری فیڈ بیک کی ضرورت والے کاموں کے لیے مفید ہے۔

### ایکشنز
ایکشنز طویل چلنے والے کاموں کے لیے استعمال ہوتے ہیں جن میں مکمل ہونے میں کافی وقت لگ سکتا ہے۔ وہ انجام دہی کے دوران فیڈ بیک فراہم کرتے ہیں اور اگر ضرورت ہو تو انہیں روکا جا سکتا ہے۔ ایکشنز نیویگیشن، مینیپولیشن، اور دیگر پیچیدہ روبوٹ رویوں کے لیے بہترین ہیں۔

## DDS مواصلاتی لیئر

ROS 2 DDS (ڈیٹا ڈسٹری بیوشن سروس) کو اس کے بنیادی مواصلاتی مڈل ویئر کے طور پر استعمال کرتا ہے۔ DDS معیار کی خدمات (QoS) کی پالیسیز فراہم کرتا ہے جو مواصلاتی رویے کی باریک ترتیب کی اجازت دیتا ہے، جیسے قابل اعتماد، م durable، اور ڈیڈ لائن کی ضروریات۔

## عملی مثال

ROS 2 تصورات کو ظاہر کرنے کے لیے آئیں ہم ایک سادہ شائع کنندہ-سبسکرائیب مثال بناتے ہیں:

```python
# publisher_node.py
import rclpy
from rclpy.node import Node
from std_msgs.msg import String

class MinimalPublisher(Node):
    def __init__(self):
        super().__init__('minimal_publisher')
        self.publisher = self.create_publisher(String, 'topic', 10)
        timer_period = 0.5  # seconds
        self.timer = self.create_timer(timer_period, self.timer_callback)
        self.i = 0

    def timer_callback(self):
        msg = String()
        msg.data = f'Hello World: {self.i}'
        self.publisher.publish(msg)
        self.get_logger().info(f'Publishing: "{msg.data}"')
        self.i += 1

def main(args=None):
    rclpy.init(args=args)
    minimal_publisher = MinimalPublisher()
    rclpy.spin(minimal_publisher)
    minimal_publisher.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

## خلاصہ

اس باب میں، ہم نے ROS 2 آرکیٹیکچر کے بنیادی تصورات کو احاطہ کیا ہے۔ ان تصورات کو سمجھنا پیچیدہ روبوٹکس سسٹم تیار کرنے کے لیے اہم ہے۔ اگلے باب میں، ہم ROS 2 کی مواصلاتی بنیاد کے تحت DDS مواصلاتی ماڈل میں مزید گہرائی سے جائیں گے۔
